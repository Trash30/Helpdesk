3. Mécanique commune (à reprendre telle quelle)

BriqueFonctionnement
OrchestrationfetchAllMatches() lance toutes les sources en parallèle avec Promise.allSettled. Une source qui plante renvoie [] et ne casse pas les autres.
CacheEn mémoire du processus, une entrée par source. Expiration à 23h59 du jour de la récupération (pas de TTL fixe), pour que les matchs du jour restent visibles une fois joués, les sites retirant les matchs terminés de leur page.
Fenêtre temporelleisInCurrentWeek() : semaine ISO lundi-dimanche calculée en fuseau Europe/Paris, quel que soit le fuseau du serveur.
Modèle communInterface Match : competition, homeTeam, awayTeam, date (ISO), time ("HH:mm" ou vide), venue, country, discipline, gender, logos et logo du diffuseur. Tri final par date croissante.
Client HTTPaxios, timeout 10 s, User-Agent de navigateur, Accept-Language: fr-FR.
ExpositionGET /api/sports/matches (authentifié) et POST /api/sports/refresh (permission tickets.create, cooldown 30 s, vide le cache). Logs émis uniquement hors production.
Préférences utilisateurFiltrage par compétition suivie côté client (user.sportCompetitions). Le serveur valide la liste autorisée dans PATCH /auth/sport-competitions.

4. Checklist : ajouter une compétition

  1. Ajouter la valeur au type Match['competition'].
  2. Écrire scrapeXxx(): Promise<Match[]> : capturer les erreurs, renvoyer [] en cas d'échec, filtrer avec isInCurrentWeek.
  3. L'ajouter au tableau sources de fetchAllMatches (clé de cache unique).
  4. Serveur : l'ajouter à VALID_COMPETITIONS (routes/auth.ts).
  5. Client : type Competition, COMPETITION_META et COMPETITION_ORDER du widget, et liste du profil.

5. Limites à connaître avant de transposer

  • Tout repose sur du scraping de pages publiques non contractuelles, sans API officielle. Une refonte de site peut casser une source silencieusement : le scraper renvoie []. Pour un outil interne, prévoir une alerte quand une source passe à 0 résultat.
  • Le cache est en mémoire du processus : perdu à chaque redémarrage, non partagé entre instances.
  • Les valeurs propres à une saison (LNH seasons_id/key, URL de saison ELMS, league_id estonien) sont à revoir chaque année.
